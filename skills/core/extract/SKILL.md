# Extract

Use the session and preceding outcome as evidence. If the user specifies an artifact type or destination, go directly to that extraction. Otherwise identify grounded candidates, intended consumers, existing homes, and whether capture is worthwhile. Nothing needing extraction is a valid result.

Check current destination artifacts before writing. Separate agreed decisions from proposals; completed work from future work; transferable learnings from local circumstances; final understanding from abandoned approaches. Preserve rationale where needed, consolidate overlaps, and update an existing artifact when that is the right home.

Choose the output by purpose:
- Documentation: describe the resulting state and behaviour.
- Future work: capture actual remaining work, dependencies, and uncertainty; do not promote casual ideas into commitments.
- Decisions: preserve the choice, reasons, alternatives, and consequences.
- Learnings: distinguish observed failures, explanations, and improvement hypotheses.
- Skills: capture a repeatable method or justified revision, using improve-skill where applicable.

Resolve material ambiguity under the interaction policy. Save the artifact in its authorised durable home: repository documentation, issue tracker when authorised, or another established destination. Avoid duplicating repo-backed content elsewhere. Report actual paths/links and distinguish saved artifacts from unpersisted candidates. Do not claim persistence if saving failed.

Compact prepares conversational context; handoff prepares another executor; extract creates durable artifacts for a particular purpose. Do not dump the transcript as a substitute for extraction.
