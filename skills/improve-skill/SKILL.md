# Improve Skill

Locate the canonical skill, its owner, scope, and upstream relationship. Read the current skill and relevant execution artifacts. For a new skill, start from a concrete process that was actually exercised. Preserve user corrections and reasons without converting every incidental step into a requirement.

Diagnose each consequential friction:
- Missing, ambiguous, contradictory, or impractical instructions.
- Failure to follow adequate instructions.
- A task-specific exception.
- Changed judgement about the process.

These need different responses. Do not automatically add a rule for every failure. State the evidence, proposed change, intended effect, and what future execution would establish whether it helps. Keep uncertain hypotheses distinct from established guidance.

Choose the smallest coherent change: amendment, structural refactor, or recast when accumulated structure warrants reconstruction. Prefer cohesive skills over aggressive deduplication. Extract shared strategies only when responsibilities and information flow can remain clear. Separate behavioural changes from reorganisation.

Make the revision reviewable in the canonical repository. Preserve useful safeguards and inspect references, consumers, and installation links. For imported skills, retain upstream ancestry, licensing, and the base revision; do not overwrite local adaptations during synchronisation.

Check structure and references, then exercise consequential process changes on representative work in a fresh session with minimal task-local context. Do not leak expected answers or prior diagnoses into an independent evaluation. If fresh execution is unavailable, label the revision provisional and record a concrete next-use check rather than claiming it validated.

Summarise what changed, why, verification, and outstanding hypotheses. Commit authorised changes using the repo's workflow; push only within the user's authorised scope. The loop is real work → capture → fresh use → evidence → revision → fresh use. Apply the same procedure to this skill when its own execution reveals friction.
